- Work only in the intended `ReloadLightly/shinka-dreamer` repository. Check the root and origin before a push. Do not force-push or modify another project.
- Preserve Namazu's dynamic partially observed maze, keys/door/exit, moving enemies, and joint evolution of world-model updating and planning. Do not substitute another research problem.
- Evolve substantive programs and representations. Do not reduce search to parameter tuning or a small predefined catalog. Resource limits regulate execution, not permissible algorithms.
- Distinguish bug fixes from the proposed predictive-learning extension. Record implemented mechanics and any departure from the source explicitly.
- Deliver executable agents and empirical learning/evolution evidence. Test counts, scaffolds, and polished prose do not establish learning or project completion.
- Keep the evaluator and hidden environment independent of candidate code. Fixed interfaces and resource boundaries must allow the intended program search.
- Use actual upstream ShinkaEvolve and record its revision. Check callback signatures, CLI options, serialization, and resolved run settings against installed code.
- Use the subscription-backed route for all permitted LLM work. No paid API calls or silent billing fallback. Audit mutation, meta/recommendation, novelty, embeddings, and any evaluator calls separately. Credentials do not authorize spending.
- Do not change authentication, approval policies, sandbox permissions, or global Codex settings to bypass a blockage. Report the concrete blocker and continue other authorized work.
- Retain native islands, sampling, lineage, inspirations, and recommendations where available in the authorized route. Report explicitly when a feature is unavailable. Do not pretend that a single mutation model demonstrates bandit model selection, or that metadata alone enables novelty.
- Use controlled independent RNG streams and keep withheld assessment cases out of mutation context. Publish separate outcome and model metrics, with uncertainty.
- Continue ordinary reversible implementation and fixes autonomously. Keep Git commits coherent, update the README with current scientific results and useful figures, and push completed work to the verified origin when executing the handoff.
- Keep raw credentials, environment files, authentication state, caches, virtual environments, and large run databases out of Git. Commit compact results, configurations, lineage summaries and representative replays needed to understand findings.
- Do not claim this skill/context automatically exists in another Codex installation. These repository instructions are the durable handoff.
