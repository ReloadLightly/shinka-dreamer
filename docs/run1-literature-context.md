# Implementation research used in RUN 1

This is a short mapping to decisions, not a novelty or publication claim.

The [final ICLR 2026 ShinkaEvolve paper](https://proceedings.iclr.cc/paper_files/paper/2026/file/7886b9bafe76c52fd568db10ff9772df-Paper-Conference.pdf) describes sampled program parents, LLM mutation including crossover, adaptive model allocation, embedding-based novelty checks and accumulated meta guidance. These motivate the combined full-machinery treatment here. Their reported benefits on other tasks are not evidence of benefit in this maze. Paper-level terminology is checked against the installed implementation rather than assumed identical to every current option. The pinned source mapping and local adapters are in [run1-native-mapping.md](run1-native-mapping.md); the official [configuration](https://sakanaai.github.io/ShinkaEvolve/configuration/) and [bandit documentation](https://sakanaai.github.io/ShinkaEvolve/bandit_selection/) are supporting interface references. No upstream upgrade was needed.

[FrugalEvo](https://arxiv.org/html/2610.03675v1) motivates separating strategy generation from repeated implementation and assessing performance against cumulative resources. Its inspected [implementation](https://github.com/chchenhui/frugalevo/tree/82f7b739110944bf3e8737db303a302a568e7327), pinned at `82f7b739110944bf3e8737db303a302a568e7327`, contains more than a two-model split: `controller.py` can reuse or queue strategies, evaluate strong-model reference implementations and allocate implementation/refinement work; `strategy.py` records reference and implementation attempts separately. `budget_curve.py` integrates the incumbent over a fixed resource window, retaining it after an early stop and excluding later over-budget gains. RUN 1 adopts explicit all-role accounting and will retain resource-indexed progress. RUN 5, requiring separate authorization, would test a native Shinka hybrid with a same-model allocation control; this run is not a FrugalEvo reproduction. The initial shallow source clone unexpectedly included a large archived-results tree; checkout was stopped and only already downloaded Git source objects were inspected. No external benchmark was executed and no FrugalEvo provider credentials or environment were installed.

The local encoder is [BGE small English v1.5](https://huggingface.co/BAAI/bge-small-en-v1.5), using [FastEmbed](https://github.com/qdrant/fastembed)'s quantized ONNX distribution pinned in `embedding-identity.json`. It is a general text model applied to code, not a code-trained behavioral similarity guarantee. RUN 1 chunks the native source prefix by actual model-token offsets, averages genuine local vectors and normalizes them. The native judge remains conditional on cosine similarity. No embedding API billing route exists in this service.

Distinct Astra/high and Sol/high subscription calls were actually successful. The local Codex model cache lists high reasoning support; the adapter passes that value explicitly. Native usage reports the effective model. Separately, saved Codex `turn_context` metadata corroborates the actual model identifier and `high` effort for these experiment sessions; the public audit retains only these metadata fields and tool counts, never private reasoning or raw sessions. [Official model-selection guidance](https://developers.openai.com/api/docs/guides/model-selection) informed role selection; observed account access, not a documentation claim, establishes availability. Temperature and output-token settings ignored by the route are not counted as model diversity.
