# RUN 1 native Shinka implementation mapping

This is a source audit and adapter specification, not evidence that the new mechanisms improved search. RUN 1 enables the combined native machinery. Individual mechanism attribution requires a subsequent controlled comparison. The closed v3 search and paused v3 assessment remain unchanged.

The installed distribution is pinned to **9912af12d423504b8d580f4179fd15f5f88b8c50**. On 2026-10-09, the upstream GitHub API reported current `main` as **8adc053a2ce4511ad2ac310e004c530a73fb974a** (commit date 2026-10-05). Native embeddings cover **only the first 10,000 source characters**, as implemented in `edit/async_apply.py`. This truncation can miss later substantive changes. The judge receives full compared sources once triggered, but embeddings and judge opinions are not scientific novelty proofs. A locally executed sentence encoder does not establish meaningful code similarity; actual similarity distributions and conditional judge activity must be reported.

The subscription adapter is `scripts/subscription_headless.sh`, called by the native Headless provider for every LLM role. It requires `HEADLESS_BILLING=subscription`, removes paid-route environment inputs for this process and relies on Headless's explicit no-fallback enforcement. No global credentials, authentication, approvals or sandbox settings change. Native effort parsing supports `low`, `medium`, `high`, `xhigh`; RUN 1 requests and records `high`. Native `temperature` and `max_tokens` metadata are not forwarded to Codex. The fixed request timeout and all effective model identifiers must be reported honestly.

## Narrow adapter changes

`dreamer/native_run1.py` supplements the pinned implementation without editing its installation:

1. Record every actual Headless subprocess request, source prompt, response, role, route, reported tokens and monotonic elapsed time. Count readiness with mutation, repairs, novelty, summaries, insights, recommendations and prompt mutations. Stop admitting calls at the first declared resource boundary; preserve any final-call overshoot. Missing usage or unresolved prior requests blocks further calls. Local embedding inference has a separate resource record.
2. Preserve native global Python/NumPy RNG plus the bandit's dedicated `numpy.random.Generator` state. Native bandit pickle serialization omits that dedicated RNG. Preserve prompt cadence counters, native prompt archive and complete meta state; native constructor counters otherwise restart from zero. The dedicated initial bandit seed is explicit in the resolved configuration.
3. Reuse an existing generation-zero prompt archive. Native setup otherwise treats `last_generation == 0` as a new prompt archive and inserts another initial prompt on early resume.
4. Keep successful generated source attempts **before** novelty, including branches later rejected. Only an `accepted-proposal.json` captured after the native novelty path may be resubmitted directly to evaluation. A saved pre-novelty proposal cannot be silently evaluated on resume. A budget-held proposal stays pending rather than acquiring an invented outcome.
5. Persist terminal pre-evaluation failures as incorrect native program rows using the existing `_persist_failed_generation`, then apply native prompt/meta/bandit side effects once. The upstream terminal handler otherwise writes only `failure.json` and `attempt_log`, leaving such failures outside completed-generation counts. These rows consume the declared candidate budget; administrative seed copies do not.
6. Reject missing/nonfinite/zero embeddings instead of accepting the native empty-embedding bypass. Treat judge transport/empty-response failure as unavailable, preserving the proposal and stopping or recording failure as appropriate. This changes failure handling, not the native similarity rule or judge criterion.
7. Reject incomplete meta-summary batches as a whole while retaining every raw request and its cost. Upstream filters failed responses before attaching generation identifiers, which can misassign a surviving response after an earlier failure. Incomplete batches do not enter recommendation history.
8. Retain the already tested interior-blank-line Headless parser correction from `dreamer/headless_transport.py`. It changes transport fidelity for exact code edits, not algorithmic search policy.
9. Review the prospectively declared development saturation condition at 8, 12, 16, 20, 24 and 28 persisted unique slots. Three latest non-seed correct programs must each escape on every development episode and have task-score range at most .002. A match requests a normal drain checkpoint, preserving already active work. This is a development resource rule, never an assessment significance rule.

Planned checkpoints stop new assignments and drain active proposals/evaluations. Complete accepted proposals retain embedding/judge provenance for recovery. Interrupted pre-novelty sources are retained and fail closed until their exact stage is resumed; overwriting them with a newly sampled proposal is forbidden. The immutable 32-slot authorized ceiling remains separate from an invocation's smaller drain target.
